- **걸린 게이트**: 1차 빌드에서 S2(글자 수: concept 슬라이드 171자>160자, exit 질문 61자>56자), S4(수치 근거: cover kicker에 손으로 적은 "3/10차시"의 "10"이 facts에 없음), B1(넘침: goals 슬라이드가 학습 목표 3개 문장이 길어 본문 영역을 넘침), B6(A4 쪽 구성: 지도안이 4쪽으로 3쪽 한도 초과) — 4종 FAIL.
- **원인**: (1) concept 포인트의 t·caption을 너무 길게 씀. (2) 지도안/활동지에 이미 구조화 필드(meta.lesson)로 들어가는 차시 정보를 슬라이드 kicker에 또 손으로 적으면서 숫자가 겹쳐 게이트가 "출처 없는 수치"로 오인. (3) 학습 목표 문장을 슬라이드용으로 줄이지 않고 그대로 써서 3개 목표가 goals 슬라이드 본문 높이를 초과. (4) 지도안 flow의 teacher/student 배열에 두 줄씩 넣고 questions에 긴 답변을 넣어 분량이 3쪽을 넘음.
- **고친 방법**: concept의 h/t·caption을 핵심어 위주로 압축, exit 질문을 더 짧은 문장으로 재작성, kicker에서 차시 숫자 중복 표기 제거(메타 필드만 사용), 학습 목표 3개를 관찰 가능한 동사 유지한 채 더 간결하게 재작성, 지도안의 두 줄짜리 교사/학생 행동을 한 줄로 병합하고 예상 질문 답변을 짧게 정리. 재빌드·재게이트 후 14/14 ALL PASS(총 2회 반복).
- **캡처 육안 검수에서 추가로 잡은 문제**: 게이트를 통과했지만 "기울기 a" concept 슬라이드(05번)의 SVG에서 두 번째·세 번째 직선에 `v-mid`/`v-muted` 클래스를 선으로 썼더니 배경과 거의 구별되지 않아 사실상 직선 두 개가 안 보이는 상태였다(게이트는 이런 시각적 판독성 문제를 못 잡음). `v-mid`/`v-muted`는 채움(fill)용이라 선(stroke)에는 `v-accent-s`(투명도로 강약 구분)나 `v-ink-s`를 써야 한다는 것을 알게 되어 수정 후 세 직선이 모두 뚜렷이 구분되도록 고쳤다.
- **다음에 처음부터 다르게 할 것**: (1) SVG를 그릴 때 선(stroke)에는 `v-accent-s`/`v-ink-s`만 쓰고 `v-mid`/`v-muted`는 채움 전용으로 취급한다 — design.md 표에서 "채움"이라고 적힌 클래스를 stroke에 재사용하지 않는다. (2) meta에 이미 구조화된 정보(차시, 시간 등)는 kicker 등 자유 텍스트에 다시 타이핑하지 않는다 — 중복 입력이 S4(수치 근거) 오탐의 원인이 된다. (3) 목표·설명 문장은 처음부터 슬라이드 글자 수 한도(중 기준 제목 28·설명 71·전체 160자)를 어림해 초안부터 짧게 쓴다.

## 2차 회고 — 선언형 그래프(`plot`) 전환

- **배경**: 스킬이 B2-STROKE 게이트와 `{"plot": {...}}` 선언형 그래프를 새로 지원해서, 직접 그린 좌표평면(cover·hook·concept·diagram·compare 좌우)을 전부 `plot`으로 바꿨다.
- **걸린 문제 1 (실제 스킬 버그, 재현 확인함)**: `compare.left.visual`/`compare.right.visual`처럼 슬라이드 최상위가 아닌 곳에 `{"plot":...}`을 넣으면 S2(글자 수)·S4(수치 근거)가 FAIL 났다. `gate.mjs`의 `slideText()`(27행)가 최상위 `visual` 키만 제외하고 JSON.stringify하는데, `left`/`right`는 제외 목록에 없어서 그 안의 `visual` 객체(plot 스펙 전체: `x`,`y`,`height` 등 키와 숫자)가 그대로 문자열로 새서 화면 글자 수에 더해지고, S4 숫자 스캐너가 `"x":[-2,2]` 같은 배열을 "2,2" 같은 수치로 오인했다. 최상위 `s.visual`은 같은 27행에서 명시적으로 제외되고 125행에서 `barsText()`로 따로 처리되지만, `plot`을 위한 동등한 처리가 최상위 슬라이드 필드에만 있고 중첩 필드(`left.visual`/`right.visual`, 아마 `steps[].visual`도 동일)에는 없다. 스킬 파일은 고치지 않기로 해서, compare 슬라이드 좌우 그래프만 손으로 그린 SVG(올바른 stroke 클래스만 사용)로 되돌려 우회했다.
- **걸린 문제 2 (실제 스킬 버그, 재현 확인함)**: `visuals.mjs`의 `plot()`이 만드는 `<clipPath id='cf-clip-${W}-${H}'>`가 가로·세로(W·H) 값만으로 id를 정한다. `width`/`height`를 안 주면 기본값 800×640이 되는데, 한 lesson.json 안에 `plot`을 여러 장 쓰면(예: cover·hook·concept·diagram 네 장 모두 기본값 사용) 한 HTML 문서 안에 똑같은 id를 가진 `<clipPath>`가 여러 개 생긴다. 빌드된 slides.html을 직접 열어 각 svg의 `<line>` 태그를 확인해 보니 좌표·클래스는 모두 정확했는데도, 브라우저가 중복 id의 clip-path 참조를 못 찾은 듯 **직선 자체가 화면에 전혀 안 보이는** 상태였다(hook·concept 슬라이드에서 재현, 라벨 텍스트는 보이는데 선만 사라짐). 게이트는 이 문제를 전혀 못 잡는다(콘솔 오류도 안 남고 B1·B8 모두 PASS). 4장의 plot 슬라이드마다 `width`/`height`를 서로 다른 값으로 명시해 id 충돌을 없애서 해결했다.
- **걸린 문제 3 (사소함)**: concept 슬라이드처럼 한 plot에 직선을 3개 이상 그리면 라벨 자동 배치가 서로 겹쳤다(원점 근처로 두 라벨이 몰림). `lines[].at`으로 라벨 x좌표를 직접 지정해서 해결 — 문서에 `at` 필드가 있다는 건 나와 있지만 "라벨이 겹칠 수 있다"는 경고나 예시가 없어서 캡처를 보고서야 알아챘다.
- **다음에 다르게 할 것**: (1) `plot`/`bars`는 항상 슬라이드 최상위 `visual`에만 쓰고, compare의 `left.visual`/`right.visual`처럼 중첩된 자리에는 (게이트가 고쳐지기 전까지는) 쓰지 않는다. (2) 같은 lesson.json에 `plot`을 2장 이상 쓸 때는 처음부터 슬라이드마다 `width`/`height`를 명시적으로 다르게 준다(기본값 그대로 두 장 이상 쓰지 않는다). (3) 직선이 2개 이상인 plot은 빌드 직후 반드시 캡처를 열어 라벨 겹침을 확인하고, 필요하면 `at`으로 위치를 지정한다.

- **고친 것 3 — 슬라이드 7 가독성**: 검수자가 compare의 미니 그래프 두 개를 읽기 어렵다고 지적. `compare`를 없애고 `concept` 유형으로 바꿔 큰 그래프 하나(diagram 칸 크기, 800×640)에 y=2x+1(파랑)·y=2x-1(회색) 두 직선과 y절편 점을 함께 그리고, 원래 좌·우 불릿(기울기 같음/y절편 값) 3개는 `points[].h/t`로 그대로 옮겼다. S1-RUN(같은 유형 3연속 금지)도 concept(5)-diagram(6)-concept(7)로 문제없음.
